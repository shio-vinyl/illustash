# 显示名来源与后台更新

状态：现行参考，2026-10-06。名称来源与选择规则见本篇，核心数据与投影见 [TERMS_NAMES.md](TERMS_NAMES.md)，应用生命周期见 [ARCHITECTURE_DIRECTION.md](ARCHITECTURE_DIRECTION.md)。

显示名由 Rust 名称命令更新正式名称及其投影，不改变实体身份、memberships 或 assertions；名称请求和配置保留在 `name_cache`、`name_settings`。`tests/reference/web/names.py（#9 已删除）` 是兼容宿主及测试对照实现。18/19/20 → 21 迁移先备份，添加别名表、删除全部 source=danbooru 的显示名、写入确定的系列作品内置名，不重建归属，保留已有请求缓存。`Store.connect()` 注册的 SQL 显示函数使用每连接快照；创建实体的去重谓词继续使用原始 tag / 既有 aliases。

## API 与运行

- `GET /api/names` 返回 `state`、`counts`、`model_api`。状态为 `idle / running / done / error / off`，进度为 `done / total`；错误只含本地生成的说明或异常类型。
- `POST /api/names` 使用现有 token / Origin 校验。`refresh` 可传 `entity`；单实体刷新包含其父角色、同族皮肤及所属作品。后台忙时显式刷新返回 400，自动同步通知会排队补跑。
- `model_api` 操作可带 `key`（新 key；`null` 清除；省略则保留）、`model`（默认 `deepseek-chat`）、`base`（任何兼容 OpenAI 的接口地址，默认 `https://api.deepseek.com`；须为 https，本机服务可用 http）。保存仅修改设置；后续拉取才会启用翻译。`model_api_test` 使用固定小请求，返回 `{ok: true}` 或 `{ok: false, error}`。GET 只返回配置状态、末四位、模型和接口地址。旧版的 `deepseek_*` 设置会自动沿用。
- 启动及 Photos / 索引导入后自动补拉；`--no-names` 关闭后台拉取和刷新，已有显示名仍可使用。前端文件没有改动。

角色、作品优先采用 Bangumi 的中文或日文；无结果时依次使用 index 中文、index 日文、wiki 中文、模型 API 中文、可读 tag。角色的 wiki 中文（`source=wiki`）即使排在 Bangumi / index 的日文之后取得，显示时仍先于日文（中文优先）。user 数据优先于自动来源；`names.en` 保留来源提供的英文名，英文显示回退仍按约定由 tag 生成。皮肤按中文 → 可读 variant 回退，未知复合词整体回退。同来源内中文优先于日文；皮肤内置译名先于模型 API。Danbooru 原始别名（source=danbooru）不参与显示选择，只有下面规则挑出的 wiki 中文可以。本地自建实体及标为 OC 的名字保持原值。`name_source=model` 是机器翻译标识（schema 22 起由旧的 `deepseek` 迁移而来）。

`characters / entities / detail / assets / similar / suggest / index` 的实体对象附原始 `tag`，原有 `work` 不变，另附 `work_name`。角色列表及详情的 `variants` 只显示皮肤部分；完整实体名使用父角色名和皮肤名。新操作及可从历史实体 ID 还原的撤销文案使用当前显示名，原始历史文本和撤销快照不被改写。

## 原生运行与恢复

原生宿主直接提供 GET/POST `/api/names`、entities/works 的远程查询和 local-links 建议。启动按当前包的 names 偏好补拉，`--no-names` 禁止后台与显式刷新，仍可读取已有显示名及模型设置。名称文本查询（角色/作品远程搜索、后台补拉中文名、作品版权解析）的授权有两种来源（2026-10-06，#1）：`--names-network` 仅为本次进程授予；图库的持久授权由用户在界面上同意（`POST /api/names {"action":"network","allow":true|false}`），存在 `library.sqlite` 的 `prefs` 表 `names_network` 行（`{"granted_at":…}`），与启动偏好分开，撤销即删除该行。授权在每次请求时实时读取，撤销后运行中的任务下一次请求即被拒绝。`GET /api/names` 返回 `network:{authorized,this_run,granted_at}`。未授权的非本机请求报「显示名联网尚未授权」（HTTP 502），前端据此显示授权入口，其他失败显示具体原因。保存 key 和修改启动偏好不授予网络。模型 HTTP 401/403 等以本地安全错误报告，不回显服务响应、凭据或请求头。模型设置继续兼容旧 `deepseek_key`/`deepseek_model`，清除仅影响当前包。

`backend_effects.kind=names:{"entity":...,"refresh":...}` 持久绑定事件所在包，entity=null 为全范围；单实体包含父角色、同族皮肤和作品。公共 Task 身份包含 canonical 包路径、generation、会话摘要及 task_id；切库先验证替代包，再取消并等待旧任务，退出同样等待。任务与同步选择器捕获原包路径及取消标记，迟到响应不能写入新包或返回新会话。底层 HTTP 每次 25 秒超时，取消期间等待在途 I/O 超时后收尾；等待节流/退避时每 20 ms 检查取消。

自动补拉复用版本 1 完成键及范围来源摘要，来源变化重新检查；刷新绕过该范围缓存，同一次消费中的重复事件合并。当前原生文本任务顺序完成作品、角色、皮肤；全进程按主机串行限制请求，沿用下面的最小起点间隔、重试、冷却、响应限制和流量预算。原生请求不持有应用事务。成功的自动名称、搜索别名、正式投影和完成键同事务提交；提交前重查来源指纹，变更时保留可重试事件。完成事件另有确认边界，确认失败及进程中断后幂等重放；失败不写负查询缓存。失败事件保留 pending 与安全错误，重启或手动刷新可重试；周期重试在连续失败后按 1、2、4……分钟加倍，最长 60 分钟，成功一次后回到 1 分钟（2026-10-21，#275）；新的事件继续处理。全库一轮在第一个条目之前就记下来源摘要（来源变了或强制刷新时先清掉旧的完成键），所以一轮里个别条目失败时，已完成的条目保留完成键，下一轮只重做失败的条目；原来要整轮成功才记摘要，一个条目失败就让下一轮全部重跑。研究发布在复核输入时，名称拉取暂停提交，复核结束再继续。只因未授权而没查成的事件同样保留 pending，但任务状态记为 `unauthorized` 而不是 `error`（同一轮有其他失败时仍报那个失败），任务页显示「未允许联网查询」和授权入口所在位置，不显示为获取失败；处于该状态且仍未授权时不做 60 秒周期重试，只处理新事件，授权后立即重试（2026-10-16，#166）。本机内置名、索引名和已有缓存在未授权时照常写入。后续同步/索引导入方可同事务入队相同 names 请求，不直接确认名称完成。

`ILLUSTASH_COPYRIGHT_BASE` 与 `ILLUSTASH_BANGUMI_BASE` 只允许显式端口的本机 HTTP 合成服务覆盖默认地址。生产查询沿用 HTTPS，缓存键保留旧 urlencode/JSON 格式；本地版权快捷路径在外查前运行。兼容模式回退需退出原生宿主后启动原兼容入口；兼容事件消费者保留 names 请求，不把通知计作已执行。没有库格式升级或兼容表删除。

2026-10-01 的合成小包（3 张资产、2 个角色、1 部作品）与本机文本服务验收：热身一次后强制刷新三次中位数，兼容 Python 为 175 ms、原生 Rust 为 43 ms。单次空闲 RSS 为 53.59 / 16.19 MiB；Python 测试宿主包含对照 HTTP 和 fixture，不含独立核心进程。此口径内未出现内存或延迟退化，未测峰值、真实网络、大图库或 Windows。

## 拉取边界

只处理有 memberships / candidates 的外部实体、其父角色、作品及皮肤词；全库刷新不会抓整个外部索引。图库搜索匹配所有来源名字、可读 tag、既有 aliases 和作品名，作品搜索返回同作品角色。

Danbooru 仅请求 wiki `title,other_names`，全部 other_names 保存为无语言标签的搜索别名，不作为显示名。唯一例外是角色的 wiki 中文：按 wiki 原顺序取第一个可用作简体中文的别名，存为 `source=wiki` 的 zh 显示名。可用的条件：不含假名、谚文，含汉字且不超过 20 字，去掉末尾的「(作品)」后全部字符在 GB2312 内（排除繁体和日文新字体，如 螢、綾、桜），不是团体名，不包含作品自身的中文名（如「重返未来6」）。日文也写得出的汉字名（如 杉山清美）只有在它前面没有别的汉字写法（如 左衛門佐）时才采用。悬停提示显示「来自 Danbooru 别名」。只用已拉取的 wiki 缓存，不增加请求。角色查询优先用 index 的 name_ja，其次按 wiki 原顺序选含假名或汉字的词，排除括号和超过 40 个规范化字符的词，最多三个不同关键词。

角色独立调用 Bangumi `search/characters?limit=10`，结果原名须与任意 index/wiki 候选名规范化后完全相等；优先采用与本次查询词精确相等的结果，防止 wiki 里的宽泛别名拉进无关角色。单一命中直接采用搜索结果的 name 和 infobox，不再请求角色详情。中文原作的 Bangumi name 存为 zh，infobox 简体中文名仅作为搜索别名；已知日本系列（例如东方、Fate、VOCALOID、Persona 3）的全汉字角色名仍存为 ja。中文原作的判断使用作品原作语言、同名 subject 和 wiki 精确别名证据；纯韩文原名不写入 zh/ja，纯拉丁字母原名写入 en。同名多结果查询各自关联 subjects，用作品候选名精确比对 name/name_cn；无法由作品区分时，只有全部候选的中文显示名完全一致才采用。作品查询失败不阻止角色查询。

作品查询同时匹配 name 和 name_cn，因此中文候选名可匹配带副标题的原名。多个命中若 name_cn 一致直接采用；否则只保留 name_cn 命中候选名的结果，再有歧义则放弃。规范化处理全半角、空格、中点及 Danbooru 的下划线空格编码。

系列级版权 tag 使用确定的内置中文名（source=builtin，用户自定义名仍优先）；Bangumi 为这些 tag 找到的单一动画或游戏条目不覆盖系列名。搜索先用 SQLite 的实体、别名和名字表生成匹配实体集与精确/前缀/包含排序，再查角色和图片，不在每一张图片或每一个角色上运行 Python 搜索 UDF。

请求和负结果永久缓存在本地。重新拉取绕过选定范围缓存；网络失败不写负缓存，下次再试。每个主机最多两个并发文本请求；Danbooru 请求起点至少间隔 0.35 秒，Bangumi 至少间隔 0.6 秒，模型 API 及其他主机至少间隔 1 秒。兼容宿主的作品和角色各由两个 wiki 工人与两个 Bangumi 工人流水线处理；作品全部处理后才用作品语言判定角色。内置系列名跳过不必要的 Bangumi 作品搜索；重复查询键在同一次运行及本地缓存中去重。25 秒超时，单响应最大 2 MB。超时、连接错误、HTTP 429/5xx 最多尝试三次，指数退避附抖动并遵守 Retry-After；每个主机连续失败 20 次后暂停 180 秒。失败不写负缓存，状态保留安全的错误类型；重启继续补拉。持久流量预算在每次请求前预留上限，成功后扣回差额；瞬时连接失败按保守的 64 KB 计费，达到 500 MB 前停止并报告需要批准。网络期间不持有数据库事务。模型 API 同样只接收 tag、日文名、作品名，无图片、图片路径或特征。

Key 存在本地 SQLite，随用户现有数据库备份机制进入本地备份；清除操作删除当前库的设置，不修改历史备份。请求错误不回显远端响应体、请求头或 key。

参考规范：[Bangumi API](https://github.com/bangumi/api/blob/master/open-api/v0.yaml)、[Bangumi User-Agent](https://github.com/bangumi/api/blob/master/docs-raw/user%20agent.md)、[Danbooru WikiPage](https://github.com/danbooru/danbooru/blob/master/app/models/wiki_page.rb)。
